🚀 Getting Started

Not on PyPI yet

FFTjax is under active development and hasn't been published to PyPI. Install it directly from source in editable mode.

💿 Installation​

  • 🖥️ CPU
  • Nvidia GPU (CUDA)
  • Google TPU
  • AMD GPU (ROCm)
git clone https://github.com/choROPeNt/FFTjax.git
cd FFTjax
pip install -e .
git clone https://github.com/choROPeNt/FFTjax.git
cd FFTjax
pip install -e ".[cuda]"
git clone https://github.com/choROPeNt/FFTjax.git
cd FFTjax
pip install -e ".[tpu]"
Single precision, automatically

TPUs don't support float64 natively — double precision is emulated and impractically slow. FFTjax detects this itself (via jax.default_backend()) and runs in float32 on TPU automatically, no configuration needed. That still means the CG tolerances this project tunes for float64 (see the smoke test below) may need loosening, and results should be checked against a CPU/GPU float64 run before trusting them. To force float64 on TPU anyway (accepting the performance cost), set JAX_ENABLE_X64=1 in the environment before running — an explicit value there is always respected over the automatic detection.

git clone https://github.com/choROPeNt/FFTjax.git
cd FFTjax
pip install -e .
pip install -U "jax[rocm]"
Untested

JAX provides a ROCm build for AMD GPUs on Linux, but this path has not been tested with FFTjax — no rocm extra is declared in pyproject.toml yet, so it's installed directly above. Verify with the smoke test below before relying on it.

The cuda and tpu extras are defined in pyproject.toml as jax[cuda12] and jax[tpu], respectively, so the accelerator-specific jaxlib build is resolved and installed directly, rather than installing the CPU build first and upgrading it to the target backend afterward.

JAX auto-configuration

Importing any FFTjax module configures JAX automatically (src/utils/precision.py):

  • Precision: float64 on CPU/GPU, float32 on TPU — detected via jax.default_backend(). An explicit JAX_ENABLE_X64 already set in the environment is always respected instead of the automatic choice.
  • GPU memory: XLA_PYTHON_CLIENT_PREALLOCATE defaults to false, so JAX grows GPU memory usage as needed instead of reserving ~75% of it upfront on first use — friendlier to sharing a GPU with other processes. Set it explicitly to true in the environment before importing FFTjax if you want the old upfront-allocation behavior back.

Editable installation (pip install -e) links the package to the local src/ tree by reference instead of copying it, so changes to the source are reflected immediately without reinstallation — relevant given the package's active development and correspondingly frequent interface changes.

✅ Verify​

Check the package installed:

python -c "from importlib.metadata import version; print(version('fftjax'))"

Then run a full smoke test — builds a frequency grid, assembles an elastic stiffness field, and runs one Newton-CG strain solve, so a pass means JAX, the accelerator-aware precision configuration, and the FFT solver machinery are all actually working, not just importable. No manual precision setup needed — importing operators.green already configures it:

python - <<'PY'
import jax
from operators.green import build_freq_grid, build_green_operator
from mat_models.elastic import LinearElasticIsotropic, assemble_C_field
from solvers.mechanical.strain_nw_cg import solve_elastic
import jax.numpy as jnp

n, L = (8, 8, 8), (1.0, 1.0, 1.0)
mat = LinearElasticIsotropic(E=210e3, nu=0.3)
C_field = assemble_C_field([mat], jnp.zeros(8**3, dtype=int))
xi = build_freq_grid(n, L)
G = build_green_operator(xi, mat.lam, mat.mu)
eps_bar = jnp.array([[1e-3, 0, 0], [0, 0, 0], [0, 0, 0]])
eps, sigma, delta, it, conv = solve_elastic(n, C_field, G, eps_bar)

expected_dtype = jnp.float32 if jax.default_backend() == "tpu" else jnp.float64
actual_dtype = jnp.zeros(1).dtype
assert actual_dtype == expected_dtype, f"expected {expected_dtype}, got {actual_dtype}"
assert bool(conv), "solver did not converge"
print("backend:", jax.default_backend(), "| devices:", jax.devices())
print("dtype:", actual_dtype, "| solve converged in", int(it), "iterations")
print("FFTjax install OK")
PY
GPU/TPU install

On a GPU or TPU machine, jax.devices() above should list an accelerator, not CpuDevice. If it still shows CPU after installing the cuda/tpu extra, JAX likely fell back silently — check pip show jaxlib matches the accelerator build.

python -m pytest test/
