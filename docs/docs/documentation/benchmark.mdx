#  Benchmark

## Frequency grid construction

Scaling of `operators.green.build_freq_grid` — the frequency-grid construction used by every
FFT-based solver — comparing plain NumPy, eager JAX, and JIT-compiled JAX across grid sizes from
8³ to 160³.

:::note[How to read it]
- **JAX eager** re-traces the function on every call, so at small grid sizes it's dominated by
  Python/tracing overhead rather than FFT work — this is expected and why **JAX JIT** (traced once,
  then replayed) is the number that matters for repeated solves.

  plain table. The chart follows the page's light/dark theme.
:::

## Linear-elastic solve: reference-medium vs. displacement-based

FFTjax's two elastic solver formulations ([`problems.mechanics.solve_mechanics`](https://github.com/choROPeNt/FFTjax),
`formulation="lippmann_schwinger"` vs. `formulation="displacement"`), swept over grid resolution on
a fixed quad_rve (square-packed 2-fibre composite, `generation.rve.make_square_composite_rve`):
glass fibre in an epoxy matrix (E=70 GPa vs. 3 GPa, ν=0.20/0.35, Vf≈50%), under a prescribed
macroscopic shear strain. Unlike a homogeneous material — where a reference-medium correction is
exactly zero — this ~23x contrast makes both solvers' CG actually iterate, so **Compile** (first
call: trace + XLA compile + run) and **Run** (steady-state, already compiled) reflect real solve
cost.

:::note[How to read it]
- Both formulations solve the *identical* problem here (pure strain BC, `control` all zero) — the
  displacement-based solver's mixed-BC capability isn't exercised, only its true-heterogeneous-
  tangent CG system versus the reference-medium correction.
- Either solver stops as soon as it converges (`jax.scipy.sparse.linalg.cg`, early-exit via
  `jax.lax.while_loop`), so **Compile**/**Run** reflect the actual, data-dependent solve cost —
  `maxiter` here is just a generous safety cap, not a real cost.
- This is CPU-only data on the machine that generated it; a GPU run would shift **Run** down
  substantially.
:::

```bash
python benchmark/benchmark_lin_elastic_solve.py
```
